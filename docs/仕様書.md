# Git GUI Windows App 現行仕様書

## 1. 概要

Git GUI Windows Appは、ローカルGitリポジトリの状態・変更・差分・コミット履歴を確認し、基本的なローカルGit操作をJavaFXで実行するデスクトップアプリケーションである。

メッセージ管理機能やSQLiteによるデータ管理は行わない。Gitが管理する状態を操作の都度取得し、アプリ固有の設定だけをユーザー領域に保存する。

### 1.1 対応環境

| 項目 | 現行仕様 |
|---|---|
| 対応OS | Windows 10/11を正式対象とする。JavaFXが動作するmacOS/Linuxでも利用可能 |
| Java | 24以上 |
| JavaFX | 26.0.2 |
| Maven | 3.6以上 |
| Git | 2.30以上を想定 |
| 表示言語 | 日本語 |
| パッケージ | `com.example.gitguiwindowsapp` |
| Mavenバージョン | `pom.xml`では0.8.1 |

## 2. 起動と初期化

### 2.1 起動

- エントリーポイントは`com.example.gitguiwindowsapp.GitGuiWindowsApp`である。
- Mavenからは`mvnw.cmd javafx:run`または`mvn javafx:run`で起動する。
- ウィンドウタイトルは`Git GUI Windows App`である。
- 最小ウィンドウサイズは760×480である。
- ウィンドウサイズ・位置は設定から復元し、終了時に保存する。
- 既定のテーマはライトモードである。

### 2.2 起動時の設定読み込み

設定ファイルは次の場所に保存する。

```text
%USERPROFILE%\.git-gui-windows-app\settings.properties
```

保存対象は次のとおりである。

- ダークモードの有効・無効
- ウィンドウの幅・高さ
- ウィンドウのX・Y座標
- Git実行ファイル
- 「開く...」ダイアログの基準フォルダー
- 最近開いたリポジトリ

設定ファイルが存在しない場合は既定値で起動する。数値が不正または有限値でない場合は、該当項目だけ既定値へ戻す。未知のキーは無視する。

最近開いたリポジトリが存在する場合、先頭のリポジトリを起動時に自動で開く。開けない場合はGitエラーを表示し、アプリケーション自体は継続する。

## 3. メイン画面

画面は`BorderPane`を基盤とし、上部のリポジトリ・ブランチ操作、中央のタブ、下部の変更操作から構成する。

### 3.1 上部ツールバー

左から次のコントロールを配置する。

| コントロール | 動作 |
|---|---|
| リポジトリパス欄 | 現在開いているリポジトリの正規化済みパスを表示 |
| 「開く...」 | フォルダー選択ダイアログを開く |
| 「基準フォルダー...」 | フォルダー選択ダイアログの初期フォルダーを設定 |
| 「更新」 | リポジトリ状態とブランチ一覧を再取得 |
| リポジトリ情報 | ルートパス、ブランチ、`clean`または「変更あり」を表示 |
| ブランチコンボボックス | ローカルブランチ一覧から対象を選択 |
| 「切替」 | 選択したブランチへ切り替え |
| 「新規ブランチ」 | ブランチ名入力ダイアログを開いて作成 |
| 「削除」 | 選択したマージ済みブランチを削除 |
| テーマ切替 | ライトモードとダークモードを切り替え |

リポジトリ未選択時やGit操作中は、実行できないボタンを無効化する。

### 3.2 「変更」タブ

左側に変更ファイル一覧、右側に選択ファイルの差分を表示する。

変更ファイル一覧の列は次のとおりである。

- ファイル: パス
- 変更: `FileChangeType`に対応する変更種別
- 状態: `StageState`に対応するステージ状態

一覧のプレースホルダーは「変更ファイルはありません」である。ファイルを選択すると、選択ファイルの差分を非同期に取得して表示する。

### 3.3 「履歴」タブ

左側にコミット履歴、右側に選択コミットの詳細を表示する。

履歴上部の検索欄では、次の項目を大文字・小文字を区別せず検索する。

- コミット件名
- コミット本文
- 作者名
- 作者メールアドレス
- 参照名

履歴一覧には、コミットグラフ、参照バッジ、件名、短縮ID、作者、コミット日を表示する。

コミット詳細には次を表示する。

- 完全なコミットID
- 作者名とメールアドレス
- コミット日時
- 親コミット
- 参照
- コミット本文

履歴は`git log --all --max-count=500`で取得する。HEAD、ローカルブランチ、リモート追跡ブランチ、タグを参照として表示する。

### 3.4 下部アクションバー

| コントロール | 動作 |
|---|---|
| 「ステージ」 | 選択ファイルをステージ |
| 「アンステージ」 | 選択ファイルをアンステージ |
| コミットメッセージ欄 | コミットメッセージを入力 |
| 「コミット」 | ステージ済み変更をコミット |
| 「履歴を更新」 | コミット履歴を再取得 |
| 状態ラベル | 準備中、処理中、完了、エラーなどを表示 |

## 4. リポジトリ操作

### 4.1 リポジトリを開く

1. 「開く...」でフォルダーを選択する。
2. `git rev-parse --show-toplevel`を選択フォルダーで実行する。
3. Gitが返したルートを実パスへ正規化する。
4. `status`とブランチ一覧を取得する。
5. 画面を更新し、最近使用したリポジトリへ追加する。
6. コミット履歴を取得する。

Git管理外のフォルダー、存在しないフォルダー、Git実行に失敗した場合は開く処理を失敗させ、エラーダイアログを表示する。

### 4.2 状態更新

状態取得には次のコマンドを使用する。

```text
git status --porcelain=v1 -z --branch
git rev-parse --verify HEAD
```

取得した状態は`RepositoryInfo`へ変換する。

- `root`: リポジトリルート
- `branch`: 現在のブランチ。空の場合は`(detached HEAD)`
- `head`: HEADの完全なコミットID。未コミット状態などで取得できない場合は空文字
- `changes`: 変更ファイル一覧
- `clean`: 変更ファイルがない場合に`true`

定期的な自動ポーリングは行わない。「更新」またはアプリ内操作完了後に取得する。

## 5. 変更と差分

### 5.1 変更状態

`GitStatusParser`はporcelain v1のX/Y状態を`FileChange`へ変換する。

対応する変更種別は次のとおりである。

- 追加
- 変更
- 削除
- リネーム
- コピー
- 未追跡
- 未マージ
- 不明

ステージ状態は次のとおりである。

- `STAGED`: インデックスだけに変更がある
- `UNSTAGED`: 作業ツリーだけに変更がある
- `BOTH`: インデックスと作業ツリーの両方に変更がある
- `UNTRACKED`: 未追跡ファイル
- `UNMERGED`: 競合状態
- `CLEAN`: 変更なし

### 5.2 差分取得

未ステージ差分には次を使用する。

```text
git diff --no-ext-diff --unified=3 -- <path>
```

ステージ済み差分には`--cached`を追加する。

```text
git diff --no-ext-diff --unified=3 --cached -- <path>
```

差分行は次の種類に分類して表示する。

- ヘッダー
- ハンク
- 追加行
- 削除行
- コンテキスト行
- メタ情報

UTF-8換算で10 MiBを超える差分は表示せず、「差分が10 MBを超えるため表示できません。」と表示する。バイナリ差分は内容を表示せず、「バイナリファイルのため内容を表示できません。」と表示する。

## 6. Git操作

### 6.1 ステージ・アンステージ

選択ファイルに対して次のコマンドを実行する。

```text
git add -- <path>
git reset -- <path>
```

操作はファイル単位で行う。複数選択、ハンク単位、行単位のステージには対応しない。

### 6.2 コミット

コミット前にコミットメッセージが空白のみでないことを確認する。

```text
git commit -m <message>
git rev-parse --verify HEAD
```

コミット成功時は新しいHEADを取得し、操作結果にコミットIDを保持する。成功後はコミットメッセージ欄をクリアし、リポジトリ状態を再取得する。

Gitフック、ユーザー設定、ステージ済み変更なしなどで失敗した場合は、Gitの標準エラーをエラーダイアログに表示する。

### 6.3 ブランチ

ブランチ一覧は次で取得する。

```text
git branch --format=%(refname:short)%09%(HEAD)
git branch --format=%(refname:short) --merged
```

新規作成、切替、削除には次を使用する。

```text
git check-ref-format --branch <name>
git branch <name>
git switch <name>
git branch -d <name>
```

以下の安全制御を行う。

- Gitの参照名規則に合わないブランチ名は拒否する。
- 未コミット変更がある場合の切替には確認ダイアログを表示する。
- 現在のブランチは削除ボタンを無効化する。
- 未マージブランチは削除ボタンを無効化する。
- 削除対象はマージ済みのローカルブランチに限定する。

## 7. Git実行とエラー処理

### 7.1 実行方式

`GitCommandRunner`は`ProcessBuilder`を使用し、実行ファイルと引数を別々に渡す。シェルコマンド文字列は組み立てない。

- 作業ディレクトリが存在しない場合は実行前に失敗する。
- 標準出力と標準エラーを別々に読み取る。
- UTF-8で出力をデコードする。
- Gitプロセスの終了コードと実行時間を記録する。
- 割り込み時はプロセスを強制終了し、割り込み状態を復元する。

### 7.2 エラー表示

非同期処理はJavaFXの`Task`とデーモンスレッドで実行する。実行中は関連ボタンを無効化し、状態ラベルを更新する。

- `GitCommandException`: Git操作名とGitのエラー内容を表示
- その他の例外: 例外メッセージまたは「不明なエラー」を表示
- 設定保存失敗: Javaのロガーへ警告を記録

Gitエラーを握りつぶしたり、失敗を成功表示したりしない。

## 8. 表示テーマとスタイル

### 8.1 ライトモード

- 背景は淡いグレーまたは白
- GitHub系の配色で変更行を表示
- 差分の追加行は緑、削除行は赤、ヘッダーは青、ハンクは紫
- 差分・履歴はConsolasを使用する

### 8.2 ダークモード

- `.dark`スタイルクラスをルートへ追加する。
- 背景、テキスト、入力欄、表、リスト、タブ、ダイアログを暗色へ切り替える。
- 差分の意味（追加、削除、ヘッダー、ハンク、メタ情報）は色分けを維持する。
- テーマ設定は設定ファイルへ保存する。

## 9. 内部構造

```text
com.example.gitguiwindowsapp
├─ GitGuiWindowsApp.java       JavaFX画面、画面イベント、非同期処理
├─ config
│  └─ ApplicationSettings.java 設定の読み書きと既定値
├─ git
│  ├─ GitCommandRunner.java    Gitプロセス実行
│  ├─ GitCommandResult.java    終了コード・出力・実行時間
│  ├─ GitCommandException.java Git実行エラー
│  ├─ GitService.java          リポジトリ操作のサービス
│  └─ *Parser.java             Git出力の解析
├─ model                       不変のドメインモデル
└─ ui
   └─ CommitGraphView.java     コミットグラフの描画
```

主なモデルは次のとおりである。

- `RepositoryInfo`: リポジトリ状態
- `FileChange`: ファイル変更
- `BranchInfo`: ブランチ情報
- `DiffDocument`、`DiffFile`、`DiffLine`: 差分情報
- `CommitEntry`、`CommitReference`、`GraphSegment`: 履歴とグラフ情報
- `GitOperationResult`: Git変更操作の結果
- `ApplicationSettings`: アプリケーション設定

## 10. テスト仕様

JUnitによるヘッドレステストを提供する。

| テストクラス | 対象 |
|---|---|
| `GitCommandRunnerTest` | 引数分離、出力、終了コード、実行失敗 |
| `GitStatusParserTest` | porcelain status、ブランチ、変更種別、ステージ状態 |
| `GitDiffParserTest` | unified diff、バイナリ、10 MiB超過 |
| `GitServiceTest` | リポジトリ検証、stage、unstage、commit、branch、履歴 |
| `ApplicationSettingsTest` | 設定の保存、読み込み、既定値、破損値 |

`GitServiceTest`は一時ディレクトリへGitリポジトリを作成し、実際のGitコマンドを使って検証する。

標準的な検証コマンドは次のとおりである。

```cmd
mvnw.cmd clean install
```

## 11. 現行版の対象外

次の機能は現行版にはない。

- fetch、pull、pushなどのリモート同期
- リモートURL管理や認証情報管理
- マージ、コンフリクト解決、rebase、cherry-pick、revert、reset、restore、clean
- stash、サブモジュール、LFS
- 部分ステージ、複数ファイルの一括操作
- ファイル名による変更一覧検索
- ファイル内容の編集
- インストーラーやランタイム同梱配布
- 操作履歴の終了後保存

競合解決や対象外操作が必要な場合は、Gitのエラー内容を確認し、ターミナルなどの外部ツールで実行する。
