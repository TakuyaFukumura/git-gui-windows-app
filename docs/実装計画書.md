# Git管理GUIアプリケーション 実装計画書

## 1. 目的

`docs/要件定義書.md` で確定した初版要件を、実装・テスト可能な作業単位へ分解する。

初版は、ユーザーが別途インストールしたGitを呼び出して、ローカルリポジトリの状態確認、差分確認、ファイル単位のステージ、コミット、ブランチ操作を行うJavaFXアプリケーションとする。

## 2. 現状分析

### 2.1 現在の構成

- `GitGuiWindowsApp` にJavaFX画面とメッセージ操作が集中している。
- SQLiteの接続・CRUDを `dao` パッケージで管理している。
- メッセージの入出力、バックアップ、入力検証、設定保存のクラスが存在する。
- `ApplicationSettings` はウィンドウ設定やテーマ設定を保存している。
- JavaFX、SQLite JDBC、JUnitがMaven依存関係に定義されている。
- テストはメッセージ、バックアップ、設定、入力検証を対象としている。

### 2.2 再利用するもの

- JavaFXアプリケーションの起動基盤
- Maven WrapperとJavaFX Maven Plugin
- `ApplicationSettings` の設定読み書きの考え方
- JavaFX CSSの配置方法
- JUnitによるヘッドレステストの構成

### 2.3 置き換えるもの

- メッセージ管理を実装しているメイン画面
- `dao`、メッセージモデル、メッセージ入出力、バックアップ機能
- SQLite JDBC依存関係
- メッセージ管理を前提としたテスト

既存クラスを段階的に残す必要はない。Git機能の実装を妨げるテンプレート由来コードは削除または置き換える。

## 3. 目標アーキテクチャ

```text
JavaFX UI
  └─ RepositoryController / ViewModel
       ├─ GitService
       │    └─ GitCommandRunner
       ├─ GitStatusParser
       ├─ GitDiffParser
       ├─ RepositoryPathService
       └─ ApplicationSettings
```

### 3.1 レイヤーの責務

| レイヤー | 主な責務 |
|---|---|
| UI | 画面表示、入力受付、確認ダイアログ、キーボード操作 |
| Controller / ViewModel | UI状態、処理中状態、選択状態、画面更新 |
| GitService | status、diff、add、reset、commit、branchなどの操作 |
| GitCommandRunner | `ProcessBuilder`による外部プロセス実行、終了コード・標準出力・標準エラー取得 |
| Parser | Gitの機械可読出力をドメインモデルへ変換 |
| Model | Repository、FileChange、Branch、GitOperationなどの不変データ |
| Settings | Git実行ファイル、最近のリポジトリ、画面設定のProperties保存 |

UIから`ProcessBuilder`を直接呼び出さない。Gitコマンドの構築と出力解析を分離し、テストで差し替え可能にする。

## 4. パッケージと主要クラス

### 4.1 `git`

- `GitCommandRunner`
  - Git実行ファイルのパスと引数リストを受け取る。
  - シェルを経由せずに実行する。
  - 終了コード、標準出力、標準エラー、実行時間を返す。
  - 作業ディレクトリと文字コードを明示する。
- `GitService`
  - リポジトリ検証、状態取得、差分取得、ステージ、アンステージ、コミット、ブランチ操作を提供する。
  - Gitの失敗をドメイン例外または結果型へ変換する。
- `GitCommandException`
  - 操作名、終了コード、標準エラー、ユーザー向けメッセージを保持する。
- `GitStatusParser`
  - `git status --porcelain=v1 -z --branch`を解析する。
- `GitDiffParser`
  - `git diff --no-ext-diff --unified=...`を表示用モデルへ変換する。
- `GitBranchParser`
  - `git branch --format=...`の結果をブランチモデルへ変換する。

### 4.2 `model`

- `RepositoryInfo`
- `FileChange`
- `FileChangeType`
- `StageState`
- `BranchInfo`
- `DiffDocument`
- `GitOperationResult`

モデルは可能な限り不変にし、Gitの生出力をUIへ漏らさない。

### 4.3 `settings`

既存の`ApplicationSettings`を再設計し、以下を保存する。

- Git実行ファイルのパス
- 最近使用したリポジトリ直近5件
- ウィンドウ位置・サイズ
- テーマなど、採用した画面設定

保存先はユーザー領域のJava Propertiesファイルとする。SQLiteや操作履歴の永続化は行わない。

### 4.4 `ui`

- `GitGuiWindowsApp`
  - JavaFXの起動とステージ設定に限定する。
- `MainController`または同等の画面制御クラス
  - リポジトリ、変更ファイル、ブランチ、差分、コミット入力を1画面で管理する。
- `ErrorDialog`
  - Gitエラーと次の対処方法を共通表示する。
- `DiffCellFactory`または同等の差分表示部品
  - 追加・削除・コンテキスト行を色と文字情報で表示する。

初版ではFXML導入を必須にせず、現在のJavaコードベースの構成を維持する。ただし、画面制御が過大になった場合はFXMLとControllerへの分離を検討する。

## 5. 実装フェーズ

### Phase 0: テンプレート整理

1. メッセージ管理の画面・サービス・DAO・モデルを削除または分離する。
2. SQLite JDBC依存関係を`pom.xml`から削除する。
3. メッセージ関連テストと不要なCSS・リソースを整理する。
4. 空のJavaFX画面が起動し、Mavenテストが通る状態を作る。

完了条件: Git機能未実装でも、テンプレートのメッセージ画面が残らず、ビルド可能である。

### Phase 1: Git実行基盤

1. `GitCommandRunner`を実装する。
2. Gitの実行ファイル検出、`git --version`、設定上書きを実装する。
3. リポジトリルート判定を実装する。
4. 終了コード、標準出力、標準エラー、Git未導入時のエラーを扱う。
5. Git引数をシェル文字列として連結しないことをテストする。

完了条件: 一時Gitリポジトリを対象に、Gitバージョン確認とルート判定ができる。

### Phase 2: 状態・変更ファイル・差分

1. `git status --porcelain=v1 -z --branch`の解析を実装する。
2. ブランチ、HEAD、clean状態、変更種別、ステージ状態をモデル化する。
3. `git diff`と`git diff --cached`の取得を実装する。
4. 10 MBを超えるファイル、バイナリ、文字コード不明の差分を表示対象外として扱う。
5. メイン画面にリポジトリ情報、変更ファイル一覧、差分表示を配置する。
6. 手動更新とGit操作後の自動更新を実装する。定期ポーリングは行わない。

完了条件: 追加、変更、削除、未追跡、リネーム、ステージ済みの状態をテストリポジトリで確認できる。

### Phase 3: ステージ・アンステージ・コミット

1. ファイル単位のステージを`git add -- <path>`で実装する。
2. ファイル単位のアンステージを実装する。
3. 未追跡・特殊パスを含め、パスを引数として安全に渡す。
4. コミットメッセージの空入力を拒否する。
5. ステージ済み変更がない場合の実行抑止を実装する。
6. 実行前確認、成功時のコミットID表示、失敗時のエラー表示を実装する。

完了条件: ファイルを選択してステージし、コミットが実際のGit履歴へ反映される。

### Phase 4: ブランチ

1. ローカルブランチ一覧と現在のブランチを表示する。
2. ブランチ名の入力検証と作成を実装する。
3. 未コミット変更の有無を確認して切り替える。
4. 現在のブランチと未マージブランチを削除不可にする。
5. 安全に削除できるブランチだけを削除対象として提示する。

完了条件: ブランチ作成・切り替え・安全な削除ができ、危険な削除がUIから実行できない。

### Phase 5: 設定・起動導線・操作性

1. Git実行ファイルの設定画面を追加する。
2. 最近使用したリポジトリを直近5件保存する。
3. 前回のリポジトリを起動時に開き、失敗時は選択画面へ進む。
4. 基本操作のキーボードショートカットを追加する。
5. 処理中表示、多重実行防止、エラー詳細のコピーを追加する。
6. キーボードフォーカスと色以外の状態表現を確認する。

完了条件: 再起動後に設定と最近のリポジトリが復元され、基本操作をキーボードで実行できる。

### Phase 6: 配布・ドキュメント

1. jpackageのアプリケーションイメージを作成できるようにする。
2. Java 24以上とGit 2.30以上が必要であることを起動案内とREADMEに記載する。
3. Windows 10/11での起動、設定保存、権限エラーを確認する。
4. 初版対象外の操作と、コンフリクト解決を外部へ委譲することを記載する。

完了条件: Windows向けアプリケーションイメージを作成し、クリーンな環境で前提条件を確認できる。

## 6. テスト計画

### 6.1 単体テスト

- コマンド引数の生成とパスの安全な取り扱い
- 終了コードによる成功・失敗判定
- Gitのporcelain出力、ブランチ出力、差分出力の解析
- 空コミットメッセージ、無効ブランチ名、重複ブランチ名の検証
- 10 MB超過、バイナリ、空の差分の扱い
- Properties設定の保存、読み込み、破損時の部分復旧

### 6.2 一時リポジトリを使う結合テスト

- `git init`から初回コミットまでの状態遷移
- ファイル追加、変更、削除、リネーム、未追跡
- ファイル単位のadd、アンステージ、commit
- ブランチ作成、切り替え、削除制約
- コンフリクト検出とエラー結果
- Git未導入または存在しない実行ファイルの扱い

### 6.3 UI確認

- リポジトリ選択から状態表示までの導線
- 変更ファイル選択と差分表示
- 処理中のボタン無効化と完了後更新
- コミット成功・失敗・空入力
- ブランチ切り替え確認と削除制約
- リサイズ、キーボード操作、長いパスの表示

### 追加対象

- Git実行、結果、例外、解析、モデルを含む`git`パッケージ
- Git操作と画面状態を扱うUI制御クラス
- Git用の単体・結合テスト

実装時点で参照されていないクラスを機械的に一括削除せず、コンパイルとテストの依存関係を確認しながら整理する。

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| Git出力のロケール依存 | porcelain、format指定、`-z`を優先し、人間向け文言を解析しない |
| Windowsのパス・予約語・特殊文字 | `ProcessBuilder`へ引数リストで渡し、特殊パスを結合しない |
| 大規模リポジトリでUIが固まる | Git処理をJavaFX UIスレッド外で実行し、一覧更新をまとめる |
| 外部操作による表示の陳腐化 | 手動更新、操作後更新、競合・失敗時の再読み込み案内を実装する |
| 誤った破壊操作 | 初版対象を限定し、ブランチ削除条件と確認をサービス層でも検証する |
| Git未導入・権限不足 | 起動時診断と、原因・対処方法を含むエラー表示を実装する |
| JavaFX UIとGit処理の結合 | GitServiceとParserをJavaFX非依存にする |

## 9. 実装順序とコミット単位

1. テンプレート機能の整理と空画面化
2. Git実行基盤とモデル
3. status解析と状態表示
4. diff解析と差分表示
5. ステージ、アンステージ、コミット
6. ブランチ操作
7. 設定・起動導線・ショートカット
8. 配布設定・README更新

各段階で、対象テストを追加し、`git diff --check`とMavenテストを実行する。UI変更を含む段階では、GUI環境で`mvn javafx:run`を実行して手動確認する。

## 10. 完了判定

- 要件定義書の初版完了条件をすべて満たしている。
- メッセージ管理・SQLite依存が初版の実装から除去されている。
- Gitコマンド実行、出力解析、UI表示が分離されている。
- Git操作の失敗、競合、Git未導入を成功扱いしない。
- 自動テストが通り、Windows GUIで主要シナリオを確認できる。
- READMEと配布手順が実装内容と一致している。
