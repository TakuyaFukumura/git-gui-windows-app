# 履歴画面デザイン見直し仕様検討

## 1. 文書の目的

履歴画面を、Git のコミット履歴を時系列とブランチの分岐・統合を把握しやすい画面へ見直すための仕様検討資料である。

本書は実装仕様を確定する前の検討結果として、添付イメージを理想形の基準にする。対象はローカルリポジトリのコミット履歴表示であり、履歴データの取得、表示モデル、JavaFX の描画、選択時の詳細表示までを含む。

## 2. 現状と課題

### 2.1 現状

- `GitService.commitGraph()` が `git log --graph --all --decorate --date=short` の結果を文字列行として取得している。
- 履歴画面は `ListView<String>` で構成され、1行をそのまま等幅フォントで表示している。
- 履歴の各行は、コミット、グラフ文字、ブランチ・タグ情報を分離して扱っていない。
- 履歴行を選択しても、コミットの詳細情報や変更ファイルを表示する導線はない。
- ダークテーマは存在するが、履歴のグラフ線・参照バッジ・選択行を構造化して配色する仕様はない。

### 2.2 課題

- グラフ文字の幅やフォントに表示品質が依存し、分岐が多い履歴では読み取りにくい。
- コミットメッセージ、日時、作者、コミットID、ブランチ・タグの区別が弱い。
- 現在のブランチや選択中のコミットを視覚的に把握しにくい。
- 長いメッセージ、複数の参照、マージコミットを表示した際のレイアウト方針が未定義である。
- 行単位の文字列表示のままでは、将来のコミット詳細、右クリック操作、キーボード操作を追加しにくい。

## 3. デザイン目標

添付イメージを参考に、次の状態を目標とする。

1. グラフの線とコミットの位置から、ブランチの流れ、分岐、マージを直感的に追える。
2. コミットメッセージを主情報として読みやすく表示し、日時・作者・ID・参照を補助情報として整理する。
3. `HEAD`、現在のブランチ、タグ、リモート追跡ブランチをバッジで区別する。
4. 選択中のコミットを青系の行背景で明確に示し、フォーカス位置も失わない。
5. ダークテーマを主対象としつつ、ライトテーマでも意味とコントラストを維持する。
6. 履歴が大きくても画面操作を阻害せず、取得中・空状態・エラー状態を明示する。
7. 表示内容を構造化し、後からコミット詳細やコンテキストメニューを追加できるようにする。

## 4. 対象範囲

### 4.1 今回の対象

- 履歴タブの表示レイアウトの見直し
- コミット履歴データの構造化
- ブランチ・タグなどの参照バッジ表示
- グラフ線とノードの表示
- コミット行の選択、キーボード移動、詳細表示への準備
- ダークテーマ・ライトテーマの履歴専用スタイル
- 更新中、空履歴、取得失敗、大量履歴の表示方針

### 4.2 今回の対象外

- 履歴の書き換え（rebase、reset、revert、cherry-pick）
- リモートへの fetch、pull、push
- コミットの作成・編集・削除
- グラフ上でのドラッグ操作
- 履歴の永続キャッシュ
- 履歴画面からのコミット間 diff の完全実装

## 5. 画面構成案

### 5.1 全体

履歴タブは、上部の操作領域と下部のスクロール可能な履歴一覧で構成する。

| 領域 | 内容 |
|---|---|
| ツールバー | 履歴更新、表示対象（全ブランチ／現在のブランチ）、検索欄、表示件数または読み込み状態 |
| グラフ列 | ブランチのレーン、接続線、コミットノード |
| コミット情報列 | コミットメッセージ、参照バッジ、短縮ID、作者、日時 |
| 詳細領域 | 選択コミットの詳細。初回実装では右側ペインまたは下部ペインを候補とする |

添付イメージのように、グラフ列は左側に固定し、コミット情報列は残りの幅を使用する。横スクロールを避けるため、長いメッセージは省略表示し、ツールチップまたは詳細領域で全文を確認できるようにする。

### 5.2 コミット行

1コミットを1行の論理単位として表示する。行内の表示順は次のとおりとする。

1. グラフ線とコミットノード
2. 参照バッジ（`HEAD`、ブランチ、タグ、リモート追跡ブランチ）
3. コミットメッセージ
4. 短縮コミットID
5. 作者
6. コミット日時

添付イメージではメッセージの視認性を優先しているため、通常表示ではメッセージと参照を前面に出し、作者・日時・IDは文字サイズまたは色を一段落とす。狭いウィンドウでは作者・日時を省略し、選択時の詳細領域で表示する。

### 5.3 グラフ

- ノードは円形で表示し、通常はレーンの中央に配置する。
- 親コミットへの線は行間で連続して見えるように描画する。
- 分岐はレーンを横方向へ移動して表現する。
- マージコミットは複数の親からノードへ入る線を表示する。
- 現在のブランチのレーンはアクセント色で強調するが、色だけに依存しない。
- 選択行のノードと接続線は、行背景と同化しないように境界または明度差を付ける。
- グラフ列の幅はレーン数に応じて決めるが、最小幅と最大幅を設けて本文領域を圧迫しない。

線は `Canvas` または専用の `Region` による描画を候補とする。単純なテキストの `*`, `|`, `/`, `\` を表示する方式は、フォント差異と折り返しによる崩れを避けるため、新デザインでは採用しない。

### 5.4 参照バッジ

参照は次の種類に分類し、種別を視覚的に識別できるようにする。

| 種類 | 表示例 | 表示方針 |
|---|---|---|
| HEAD | `HEAD` | 明るいアクセント色。現在位置を示す |
| 現在のローカルブランチ | `main` | ブランチ色。現在ブランチは `HEAD` と隣接表示 |
| その他のローカルブランチ | `feature/login` | ブランチ色。長い名前は省略し、ツールチップに全文 |
| タグ | `v0.6.0` | タグ色。リリースを示す |
| リモート追跡ブランチ | `origin/main` | リモート用の控えめな色 |

バッジには文字だけでなく、必要に応じてアイコンまたは境界線を併用する。バッジの色はテーマごとに十分なコントラストを確保し、色覚差があっても種別名を読めるようにする。

## 6. 表示データ仕様

### 6.1 表示モデル

現在の `List<String>` を置き換え、少なくとも次の情報を持つ不変モデルを導入する。

### `CommitEntry`

- `id`: 完全なコミットID
- `shortId`: 表示用短縮ID
- `subject`: コミットメッセージの1行目
- `authorName`: 作者名
- `authorEmail`: 表示可否を設定で決める。初期値は非表示候補
- `committedAt`: コミット日時（ローカル表示用とソート用を分離）
- `parents`: 親コミットIDの一覧
- `references`: そのコミットに付与された参照一覧
- `graph`: 対象行のレーンと線分を表す描画情報

### `CommitReference`

- `name`: 表示名
- `type`: `HEAD`、ローカルブランチ、リモートブランチ、タグ
- `current`: 現在のブランチまたは現在のHEADに該当するか

### `GraphSegment`

- `lane`: レーン番号
- `fromLane`: 前行からの開始レーン
- `toLane`: 次行への終了レーン
- `kind`: 継続、分岐、合流、マージなど
- `highlighted`: 現在ブランチまたは選択状態による強調有無

表示モデルは Git の出力文字列を UI で再解析する前提にせず、サービス層または専用パーサーで生成する。

### 6.2 Git 出力

Git の人間向け整形結果に依存しないため、コミット情報は区切り文字を明示した `--format` で取得する。候補は次のとおりとする。

```text
git log --all --date=iso-strict --format=<区切り形式>
```

参照は `--decorate` の表示文字列を直接描画用に使わず、参照名と種別を分離して取得する。グラフのレーン計算は、コミットと親の関係を用いてアプリ側で行うか、既存の `--graph` 出力を構造化パーサーで解釈するかを比較検証する。後者を採用する場合も、UI は生のグラフ文字列を保持しない。

## 7. 操作仕様

- 履歴タブを開いた時点で、現在のリポジトリの履歴を表示する。
- 「履歴を更新」で再取得し、選択中のコミットが存在すれば選択状態を可能な限り維持する。
- 行クリックでコミットを選択する。
- 上下キーで行を移動し、Enter または Space で選択状態を確定する。
- 選択行にはフォーカスリングまたは明確な境界を表示する。
- 初期表示では全ブランチの履歴を対象とする。現在ブランチのみの絞り込みはツールバーから切り替え可能な候補とする。
- 履歴の取得中は更新操作を多重実行できないようにし、進行中であることを表示する。
- 選択コミットの詳細表示は、コミットID、完全なメッセージ、作者、日時、親、参照、変更ファイルを対象とする。ただし変更ファイルの取得は次段階でもよい。

## 8. テーマと視覚仕様

### 8.1 ダークテーマ

添付イメージを基準に、背景は濃いチャコール、本文は明るいグレー、選択行は青、現在位置やグラフ線はオレンジまたは黄色系を基本とする。線の色を増やしすぎず、レーンの識別に必要な数に限定する。

### 8.2 ライトテーマ

背景は白または薄いグレー、本文は濃いグレー、選択行は淡い青とする。グラフ線・バッジはダークテーマと同じ意味付けを保ちつつ、背景とのコントラストを調整する。

### 8.3 文字と余白

- 本文は既存の `Segoe UI` を基本とする。
- グラフ線の描画にフォント文字を使用しない。
- コミットメッセージは標準サイズ、補助情報は標準より小さくする。
- 行の高さは固定または一定範囲に収め、一覧のスクロール位置が不安定にならないようにする。
- タグ名やブランチ名が長い場合も、行の高さを増やさず省略する。

## 9. 状態・エラー表示

| 状態 | 表示 |
|---|---|
| 初期状態 | 「リポジトリを選択してください」 |
| 履歴なし | 「コミット履歴はありません」 |
| 取得中 | 履歴領域内に進行中表示。更新ボタンは無効化 |
| Git エラー | 履歴を消去せず、エラー内容と再試行導線を表示 |
| 大量履歴 | 初回表示件数を制限し、追加読み込みまたは表示件数選択を検討 |
| 破損した行 | 取得済みの他行は表示し、対象行は解析不能であることを明示 |

Git の標準エラー出力や認証情報を含む可能性のある環境変数は、履歴の表示モデルやログに保存しない。

## 10. 大規模履歴への対応

初回実装では、全件を無制限に JavaFX ノードへ変換しない。次のいずれかを採用する。

1. `ListView` の仮想化を利用し、表示モデルは取得件数を制限する。
2. `git log` に件数上限を付け、末尾到達時に追加取得する。
3. レーン計算に必要な親コミットを含めて取得し、画面表示分だけ描画する。

採用方式は、100件、1,000件、10,000件程度のリポジトリで、履歴取得時間・初回描画時間・スクロール性能を測定して決定する。

## 11. 実装方針

### Phase 1: 表示モデルと取得処理

- `CommitEntry`、`CommitReference`、グラフ描画情報のモデルを追加する。
- `GitService.commitGraph()` の文字列返却を、構造化された履歴返却へ移行する。
- パーサーの単体テストを追加する。

### Phase 2: 行セルとバッジ

- `ListView<CommitEntry>` へ変更する。
- カスタム `ListCell` でメッセージ、補助情報、参照バッジをレイアウトする。
- 選択・ホバー・フォーカス・空状態をテーマごとに整える。

### Phase 3: グラフ描画

- グラフ列を専用コンポーネント化する。
- 親子関係からレーンと線分を計算する。
- 分岐、合流、マージ、現在ブランチをテスト用履歴で確認する。

### Phase 4: 詳細表示と大規模履歴

- 選択コミットの詳細領域を追加する。
- 件数制限または追加読み込みを導入する。
- キーボード操作、アクセシビリティ、取得失敗時の再試行を仕上げる。

## 12. テスト・受け入れ基準

### 12.1 自動テスト

- 通常の直線的な履歴を正しくモデル化できる。
- ブランチ分岐とマージで親が複数の場合も解析できる。
- `HEAD`、ローカルブランチ、タグ、リモート追跡ブランチを正しく分類できる。
- 日本語、空白、タブ、長文を含むコミットメッセージを壊さず扱える。
- 不完全な Git 出力や Git の失敗を成功扱いしない。
- 履歴取得の引数にリポジトリパスや表示文字列を連結しない。

### 12.2 UI 受け入れ基準

- 添付イメージのように、グラフ・ノード・コミット情報・参照バッジを同一行で確認できる。
- 選択行が明確であり、長いメッセージや複数バッジでもレイアウトが崩れない。
- 分岐・合流・マージの線が行をまたいで連続して見える。
- ダークテーマとライトテーマの双方で、文字・線・選択状態を判別できる。
- マウスとキーボードの双方で履歴行を選択できる。
- 更新中、履歴なし、Git エラーを状態に応じて判別できる。
- 代表的な大規模履歴で、画面が長時間操作不能にならない。

## 13. 未決事項

- グラフ描画を `Canvas` と専用 `Region` のどちらで実装するか。
- `--graph` 出力の構造化パースと、親コミット関係からの独自レーン計算のどちらを採用するか。
- 初回表示件数と追加読み込みの単位。
- コミット詳細を右側ペイン、下部ペイン、ダイアログのどれで表示するか。
- 作者メールアドレスを表示するか。
- 履歴検索をコミットメッセージのみとするか、作者・参照も対象にするか。
- リモート追跡ブランチを初期表示に含めるか。
- 現在ブランチ以外のレーン色を固定パレットにするか、テーマごとに定義するか。

### 初回実装で採用する方針

- 初回実装の対象は Phase 1〜3（表示モデル、取得処理、一覧セル、参照バッジ、グラフ描画）とする。
- グラフのレーンは、`git log --graph` の文字列を再解析せず、コミットと親の関係からアプリ側で計算する。
- 初期表示はリモート追跡ブランチを含む `--all` 相当とし、取得件数は500件に制限する。
- グラフ列は各 `ListCell` 内の専用 `Region` で描画する。
- コミット詳細（ID、完全なメッセージ、作者、日時、親、参照）は Phase 4 の初回対象として右側ペインに表示する。
- 追加読み込み、作者メールアドレスの表示切り替えは後段で検討する。

## 14. 既存ドキュメントとの関係

- `docs/要件定義書.md` の「履歴、タグ、stash」は将来検討項目であるため、本仕様では履歴表示に限定して具体化する。
- `docs/実装計画書.md` の Phase 6「履歴」を、本書の Phase 1〜4へ分解する。
- 操作履歴（アプリ内で実行した Git 操作のログ）と、コミット履歴（Git リポジトリの commit log）は別概念として扱う。
