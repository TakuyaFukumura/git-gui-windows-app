# Git管理GUIアプリケーション 要件定義書

## 1. 文書の目的

本書は、ローカルのGitリポジトリをJavaFXで確認・操作するデスクトップアプリケーションの現行要件と実装状況を定義する。

本アプリケーションは、Gitのコマンドライン操作に不慣れな利用者が、リポジトリの状態、変更内容、コミット履歴を確認し、安全に基本的なローカル操作を行えることを目的とする。メッセージ管理機能やSQLiteによるデータ管理は対象外である。

### 1.1 対象環境

- Windows 10/11を正式サポート対象とする。
- Java 24以上、JavaFX 26.0.2、Maven 3.6以上を使用する。
- Git 2.30以上を、PATHまたは設定された実行ファイルから利用する。
- macOS/LinuxでもJavaFXが動作する環境では利用できる。

### 1.2 実装状況の表記

- **実装済み**: 現在のアプリケーションで利用できる機能。
- **未実装**: 将来の拡張候補であり、現行リリースの受け入れ条件には含めない。

## 2. 対象ユーザーと利用シナリオ

### 2.1 想定ユーザー

- Gitを学習中の開発者
- 小規模な個人開発を行う開発者
- コマンドラインより一覧や差分で確認したい開発者

### 2.2 代表的な利用シナリオ

1. アプリを起動し、「開く...」からローカルリポジトリを選択する。
2. 現在のブランチ、clean/変更ありの状態、変更ファイルを確認する。
3. 変更ファイルを選択して差分を確認する。
4. ファイル単位でステージまたはアンステージする。
5. コミットメッセージを入力してコミットする。
6. ブランチを作成、切り替え、または安全に削除する。
7. 「履歴」タブでコミット履歴を検索し、選択したコミットの詳細を確認する。

## 3. 機能要件

### FR-01 Git実行基盤

- Gitコマンドは`ProcessBuilder`で実行し、サブコマンドと引数を個別に渡す。
- シェルを介したコマンド文字列の組み立ては行わない。
- Gitの終了コード、標準出力、標準エラー出力を取得し、失敗時はエラーとして画面に表示する。
- Git実行ファイルは既定で`git`を使用し、設定から実行ファイルのパスを変更できる。

### FR-02 リポジトリの選択と検証

- フォルダー選択ダイアログからリポジトリを開ける。
- 選択したフォルダーを`git rev-parse --show-toplevel`で検証し、リポジトリのルートを正規化して開く。
- Git管理外のフォルダーや存在しないフォルダーは開かず、エラー内容を表示する。
- 「開く...」の基準フォルダーを設定できる。
- 最近開いたリポジトリを最大5件保存する。
- 前回開いたリポジトリが存在する場合は、起動時に自動で開く。
- 自動接続に失敗した場合はエラーを表示し、手動選択を継続できる。

### FR-03 リポジトリ状態の表示

- リポジトリのルートパス、現在のブランチ、clean/変更ありの状態を表示する。
- HEADの完全なコミットIDを内部モデルで保持する。
- `git status --porcelain=v1 -z --branch`で取得した変更を表示する。
- 「更新」で状態を再取得できる。
- Git操作の完了後は状態とブランチ一覧を自動更新する。
- コマンド実行中は処理中の表示を行い、同時操作を無効化する。
- Git処理はJavaFXのUIスレッド外で実行する。

### FR-04 変更ファイルと差分

- 変更ファイルのパス、変更種別、ステージ状態を一覧表示する。
- 未追跡、追加、変更、削除、リネームなどのGit状態をモデルへ変換する。
- ファイルを選択すると、そのファイルの差分を表示する。
- ステージ済み変更はステージ済み差分、未ステージ変更は作業ツリー差分を表示する。
- 追加行、削除行、コンテキスト、ヘッダーを視覚的に区別する。
- バイナリファイルは内容を表示せず、表示できない理由を示す。
- 1ファイル10 MBを超える差分は表示せず、上限超過を示す。
- 差分表示は閲覧専用とし、行単位・ハンク単位の編集は行わない。
- 複数選択による一括操作、変更ファイル名の検索、無視対象ファイルの表示切り替えは未実装とする。

### FR-05 ステージとアンステージ

- 選択した1ファイルをステージできる。
- ステージ済みの1ファイルをアンステージできる。
- 未追跡ファイルのステージには`git add -- <path>`を使用する。
- 操作後に変更一覧、選択状態、差分表示を更新する。
- ファイル単位の操作に限定し、複数ファイル・ハンク単位・行単位の操作は未実装とする。

### FR-06 コミット

- コミットメッセージを入力してステージ済み変更をコミットできる。
- 空または空白のみのコミットメッセージは実行しない。
- Gitのコミット結果から成功したコミットIDを取得する。
- 成功後に入力欄をクリアし、リポジトリ状態と履歴を更新する。
- ステージ済み変更がない場合やGitフックで失敗した場合は、成功と誤認させずエラーを表示する。
- コミット対象の事前確認ダイアログ、メッセージテンプレート、署名設定は未実装とする。

### FR-07 ブランチ操作

- ローカルブランチ一覧と現在のブランチを表示する。
- Gitの参照情報から、ローカルブランチ、リモート追跡ブランチ、タグをコミット履歴上に表示する。
- Gitの`check-ref-format --branch`でブランチ名を検証する。
- 新しいローカルブランチを作成できる。
- ローカルブランチを切り替えられる。
- 未コミット変更がある場合は、変更を保持したまま切り替える確認を表示する。
- 現在のブランチと未マージブランチは削除操作を無効化する。
- マージ済みのローカルブランチだけを`git branch -d`で削除できる。
- リモートブランチの作成、削除、追跡設定の変更は未実装とする。

### FR-08 コミット履歴

- `git log --all --max-count=500`でコミット履歴を取得する。
- ブランチ、リモート追跡ブランチ、タグ、HEADなどの参照をコミットに紐付けて表示する。
- コミットのグラフ、参照名、件名、短縮ID、作者、コミット日を一覧表示する。
- 選択したコミットの完全ID、作者、日時、親、参照、本文を詳細表示する。
- コミットメッセージ、作者、メールアドレス、参照名を対象に履歴を絞り込める。
- 「履歴を更新」で履歴を再取得できる。
- 履歴の改変、検索結果の永続化、ページングは未実装とする。

### FR-09 表示テーマと設定

- ライトモードとダークモードを切り替えられる。
- ウィンドウの位置とサイズを保存・復元する。
- Git実行ファイル、開くダイアログの基準フォルダー、最近使用したリポジトリを保存する。
- 設定は`%USERPROFILE%\.git-gui-windows-app\settings.properties`にJava Properties形式で保存する。
- 壊れた設定値は該当項目だけ既定値へ戻し、読み込み可能な他の設定は保持する。
- 設定の保存に失敗した場合はログへ警告を記録する。

## 4. 対象外・将来拡張

現行版では次の機能を提供しない。

- fetch、pull、pushなどのリモート同期
- リモートURLの管理、認証、OAuth、SSH鍵、credential helperの管理
- マージ、コンフリクト解決、リベース、cherry-pick、revert、reset、restore、clean
- 部分ステージ、複数選択による一括操作
- stash、タグの作成・削除、サブモジュール、LFS
- ファイル内容の編集、画像・バイナリの内容表示
- 複数リポジトリの同時操作
- 操作履歴の終了後保存、クラウド同期、権限管理
- 配布用インストーラーの提供

競合や高度なGit操作が必要な場合は、Gitのエラー内容を表示し、外部エディターまたはターミナルでの解決を前提とする。

## 5. 画面要件

### 5.1 メイン画面

- リポジトリ選択欄、「開く...」、「基準フォルダー...」、「更新」を上部に配置する。
- 上部に現在のリポジトリ、ブランチ一覧、ブランチ切替、新規ブランチ、削除、テーマ切替を配置する。
- 「変更」タブに変更ファイル一覧と選択ファイルの差分を配置する。
- 「履歴」タブに履歴検索、コミット一覧、グラフ、コミット詳細を配置する。
- 下部にステージ、アンステージ、コミットメッセージ入力、コミット、履歴更新、処理状態を配置する。
- ウィンドウの最小サイズは760×480とする。

### 5.2 ダイアログとエラー

- ブランチ作成にはブランチ名入力ダイアログを使用する。
- 未コミット変更があるブランチ切替と、マージ済みブランチの削除には確認ダイアログを表示する。
- Git実行失敗時は操作名とGitのエラー内容をエラーダイアログに表示する。
- 実行中の操作は関連ボタンを無効化し、多重実行を防止する。

## 6. 非機能要件

### NFR-01 安全性

- 外部入力をシェルコマンド文字列に連結しない。
- リポジトリパス、ファイルパス、ブランチ名、コミットメッセージを引数として分離して渡す。
- 未コミット変更があるブランチ切替では確認を要求する。
- 現在のブランチや未マージブランチの削除を許可しない。
- 認証情報、アクセストークン、秘密鍵の内容を取得・保存・表示しない。

### NFR-02 応答性と信頼性

- Gitコマンドはバックグラウンドタスクで実行し、UIスレッドをブロックしない。
- 終了コードと標準エラーを判定し、失敗を成功として扱わない。
- Gitの実行失敗後もアプリケーションを終了せず、エラーを表示して再操作できる。
- 状態の自動ポーリングは行わず、手動更新またはアプリ内操作後の更新を行う。

### NFR-03 保守性

- Git実行、出力パーサー、モデル、JavaFX UIを分離する。
- status、diff、branch、commitの出力解析を専用クラスに集約する。
- Git状態・パーサー・サービス・設定はヘッドレスのJUnitテストで検証できる構成とする。

## 7. データと状態モデル

主なモデルは次のとおりとする。

- `RepositoryInfo`: リポジトリルート、ブランチ、HEAD、変更一覧、clean状態
- `FileChange`: ファイルパス、変更種別、ステージ状態
- `BranchInfo`: ブランチ名、現在のブランチか、マージ済みか
- `DiffDocument`、`DiffFile`、`DiffLine`: 差分、ファイル、行の表示情報
- `CommitEntry`、`CommitReference`: コミットと参照情報
- `GitOperationResult`: Git操作の終了コード、出力、エラー、コミットID
- `ApplicationSettings`: Git実行ファイル、最近のリポジトリ、テーマ、ウィンドウ状態

画面状態は、おおむね次のように遷移する。

```text
未選択 → リポジトリ検証中 → 利用可能
利用可能 → Git操作中 → 利用可能
利用可能 → エラー表示 → 再試行または再読み込み
```

## 8. テスト要件と受け入れ基準

### 8.1 自動テスト

- `GitCommandRunner`の引数、終了コード、標準出力・標準エラー処理
- status、diff、commit、branch出力のパーサー
- 一時Gitリポジトリでのstatus、stage、unstage、commit、branch操作
- 空コミットメッセージと不正ブランチ名の検証
- 設定の保存、読み込み、破損値の既定値復元

### 8.2 受け入れ基準

- Gitリポジトリを選択して開き、現在のブランチと変更ファイルを確認できる。
- ファイルを選択して差分を確認できる。
- ファイルをステージ・アンステージし、ステージ済み変更をコミットできる。
- ブランチを作成・切り替え・マージ済みの場合のみ削除できる。
- 履歴を表示し、メッセージや作者などで検索し、コミット詳細を確認できる。
- Git操作の失敗が成功表示にならず、エラー内容を確認できる。
- 未コミット変更を持つブランチ切替で確認が表示される。
- 設定と最近使用したリポジトリが次回起動時に復元される。

## 9. 開発・リリース方針

- 開発中は`mvnw.cmd javafx:run`または`mvn javafx:run`で起動する。
- ビルドとテストは`mvnw.cmd clean install`または`mvn clean install`で実行する。
- Windows向けにはjpackageによるアプリケーションイメージを作成する。
- 配布物にはJavaランタイムを同梱せず、利用者がJava 24以上を別途用意する。
- Gitの必須条件、対応OS、未実装機能はREADMEと本書に反映する。
