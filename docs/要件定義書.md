# Git管理GUIアプリケーション 要件定義書

## 1. 文書の目的

本書は、ローカルのGitリポジトリをGUIで操作するシンプルなデスクトップアプリケーションの初期要件を定義する。

既存のメッセージ管理機能、SQLiteによるCRUD、テンプレート由来の画面構成は、本アプリケーションの要件とはみなさない。既存実装は必要に応じて置き換え、Git操作を中心に再設計する。

### 1.1 対象読者

- 開発担当者
- UI・操作仕様を確認する担当者
- テスト担当者
- 将来の機能追加を検討する担当者

### 1.2 初版の前提

- 対象OSはWindows 10/11とする。
- Gitはユーザーが別途インストール済みで、コマンドラインから実行できるものとする。
- 初版はローカルリポジトリの操作に限定する。
- リモートリポジトリとの同期（fetch、pull、push）は初版の対象外とする。
- リモートホスティングサービス固有の認証やAPI連携は対象外とする。
- Gitの専門用語を完全に隠すのではなく、初心者でも安全に操作できる説明を補う。

## 2. 目的と解決したい課題

### 2.1 目的

コマンドライン操作に不慣れな利用者が、現在の変更内容を確認し、コミットやブランチ操作を安全に実行できるようにする。

### 2.2 解決したい課題

- リポジトリの状態をコマンドで確認する手間がある。
- 変更されたファイルと差分の把握が難しい。
- add、commit、branch、checkoutなどの操作を個別に覚える必要がある。
- 未コミット変更を意図せず失う危険がある。
- Gitコマンドのエラー内容が初心者には分かりにくい。

### 2.3 成功条件

- リポジトリを開いてから、現在のブランチ、変更ファイル、差分を迷わず確認できる。
- 変更を選択してステージし、コミットメッセージを入力してコミットできる。
- 危険な操作では、対象と影響を確認してから実行できる。
- Gitが返したエラーを画面上で確認でき、アプリが異常終了しない。

## 3. 想定ユーザーと利用シナリオ

### 3.1 想定ユーザー

- Gitを学習中の開発者
- 小規模な個人開発を行う開発者
- コマンドラインより一覧や差分で確認したい開発者

### 3.2 代表的な利用シナリオ

1. アプリを起動し、最近使用したリポジトリを開く。
2. 現在のブランチと変更ファイルを確認する。
3. ファイルを選択して差分を確認する。
4. コミット対象を選択してステージする。
5. コミットメッセージを入力してコミットする。
6. 必要に応じてブランチを作成または切り替える。
7. 必要に応じて、次に行うGit操作を検討する。

## 4. 対象範囲

### 4.1 初版で対象とする機能

- Git実行ファイルの検出と設定
- ローカルリポジトリの選択・オープン
- 現在のブランチとHEADの表示
- 作業ツリーの状態表示
- 変更ファイルの一覧表示
- ファイル単位の差分表示
- ファイル単位のステージ・アンステージ
- ステージ済み変更のコミット
- ブランチ一覧、作成、切り替え、削除
- 操作結果とエラーの表示
- 最近開いたリポジトリの保存

### 4.2 初版で対象外とする機能

- GitHub、GitLabなどのWeb APIとの連携
- OAuth、SSH鍵、アクセストークンの管理
- GUI上での高度なマージ編集
- リベース、cherry-pick、revert、resetのGUI操作
- サブモジュールの専用管理
- 大容量バイナリの差分表示
- 複数リポジトリの同時操作
- チーム向けの権限管理や監査ログ
- クラウドへの設定同期

対象外の操作は、必要に応じて「ターミナルで実行する」導線を提供するが、アプリ内で無理に再実装しない。

## 5. 機能要件

### FR-01 Git環境の確認

- 起動時にGit実行ファイルを検出する。
- 検出できない場合は、インストールまたは実行ファイルの場所を設定する案内を表示する。
- Gitのバージョンと実行結果を診断画面で確認できる。
- Gitコマンドの実行は、引数を分離して渡し、文字列連結による意図しないコマンド実行を避ける。

### FR-02 リポジトリを開く

- フォルダー選択ダイアログからリポジトリを開ける。
- 選択フォルダーがGitリポジトリでない場合は、理由を表示して開く処理を中止する。
- `.git`が親フォルダーにある場合は、検出したリポジトリのルートを開くか確認する。
- 最後に開いたリポジトリを履歴として保存し、次回起動時に選択できる。
- 前回開いたリポジトリが存在する場合は、起動時に自動で開く。
- 前回のリポジトリを開けない場合は、理由を表示してリポジトリ選択へ進む。
- リポジトリのパスは正規化して表示する。

### FR-03 リポジトリ状態を表示する

- リポジトリ名、ルートパス、現在のブランチ、HEADの短縮ハッシュを表示する。
- 作業ツリーがcleanか、変更があるか、コンフリクト中かを表示する。
- 状態を手動更新できる。
- Git操作の完了後は自動的に状態を更新する。
- 初版では一定間隔の自動ポーリングは行わない。
- コマンド実行中は多重実行を防止し、処理中であることを表示する。
- 外部で変更された場合に、次回更新時の情報を正しく反映する。

### FR-04 変更ファイルを表示する

- 未追跡、変更、削除、リネーム、ステージ済み、未ステージの区分を表示する。
- ファイルパス、変更状態、追加行数、削除行数を表示する。
- ファイルを選択すると、対応する差分を表示する。
- 未追跡ファイルは、サイズが大きすぎる場合や無視対象の場合の状態も説明する。
- ファイル一覧をパス名で検索できる。

### FR-05 差分を表示する

- ステージ前の差分とステージ済みの差分を切り替えて表示する。
- 追加、削除、変更行を視覚的に区別する。
- UTF-8の一般的なテキストを読みやすく表示する。
- バイナリ、文字コード不明、巨大ファイルは、表示できない理由を示す。
- テキスト差分の表示対象は1ファイル10 MB以下とし、超過時は理由を表示する。
- 差分表示は閲覧専用とし、初版では行単位の編集を必須としない。

### FR-06 ステージとアンステージ

- 選択したファイルをステージできる。
- ステージ済みファイルをアンステージできる。
- 複数ファイルをまとめて操作できる。
- 初版では差分のハンク単位・行単位のステージ操作は対象外とする。
- 未追跡ファイルをステージする場合は、対象ファイルを明示する。
- 実行後に状態と差分を更新する。

### FR-07 コミット

- ステージ済みファイルの一覧と差分を確認してからコミットできる。
- コミットメッセージが空または空白のみの場合は実行できない。
- コミット前に、コミット対象とメッセージを確認できる。
- ステージ済み変更がない場合は実行できない。
- コミット成功後にコミットIDとメッセージを表示し、状態を更新する。
- フックや署名設定などにより失敗した場合は、Gitのエラー出力を保持して表示する。

### FR-08 ブランチ操作

- ローカルブランチ一覧と現在のブランチを表示する。
- 新しいブランチ名を入力して作成できる。
- ブランチを切り替えられる。
- ブランチ名の不正文字や重複を、実行前に検証する。
- 未コミット変更がある状態で切り替える場合は、影響を説明して確認する。
- 現在のブランチと未マージブランチは削除できないようにする。
- 初版では、リモート追跡ブランチとの関連表示を行う。

### FR-09 リモート同期

- リモート名とURLを表示する。ただし、認証情報やトークンは表示しない。
- fetch、pull、pushを個別の操作として提供する。
- pullやpushの前に対象リモートとブランチを確認できる。
- push先が未設定の場合は、設定不足を明示する。
- 認証要求、ネットワーク障害、コンフリクトを、成功と誤認させない形で表示する。
- 同期中は対象リポジトリに対する別操作を受け付けない。

### FR-10 操作履歴とログ

- 直近のGit操作、実行日時、成否を表示する。
- 失敗した操作について、Gitの標準エラー出力を確認できる。
- 秘密情報を含む可能性のある環境変数や認証情報をログに保存しない。
- 操作履歴はアプリ起動中だけ保持し、終了時に破棄する。

### FR-11 設定

- Git実行ファイルのパスを変更できる。
- 表示テーマ、ウィンドウサイズ、最近使用したリポジトリを保存できる。
- 設定ファイルの保存先と、保存に失敗した場合の通知方法を定義する。
- 設定値が壊れている場合は、影響する項目だけ初期値に戻し、他の設定を可能な限り保持する。

## 6. 画面要件

### 6.1 メイン画面

初版はリポジトリ操作を1画面に集約し、メイン画面を以下の領域で構成する。

- 上部: リポジトリ選択、更新、現在のブランチ、操作メニュー
- 左側: 変更ファイル一覧、ステージ状態、ブランチ一覧
- 中央または右側: 選択ファイルの差分
- 下部: ステージ、アンステージ、コミット、同期操作、処理ステータス

ウィンドウをリサイズしても、ファイル一覧と差分が確認できることを優先する。

### 6.2 コミット領域

- コミットメッセージ入力欄を提供する。
- ステージ済みファイル数と変更行数を表示する。
- 実行前確認と実行結果を同じ画面で把握できる。

### 6.3 エラー・確認ダイアログ

- 操作名、対象リポジトリ、対象ブランチまたはファイルを表示する。
- 何が起きたか、次に何を確認すべきかを日本語で説明する。
- 破壊的または取り消しにくい操作は、キャンセルを既定の選択肢とする。
- Gitの詳細出力は、必要に応じて展開表示またはコピーできる。

### 6.4 アクセシビリティ

- 主要操作をキーボードだけで実行できる。
- フォーカス位置が視認できる。
- 状態を色だけで表現せず、文字やアイコンも併用する。
- 初版ではスクリーンリーダー専用対応や高コントラストテーマは対象外とし、将来拡張として検討する。

## 7. 非機能要件

### NFR-01 対応環境

- Windows 10/11を正式サポート対象とする。
- Java 24以上、JavaFXを使用する。
- Git 2.30以上をサポート対象とする。

### NFR-02 応答性

- 状態取得や差分取得をUIスレッドで同期実行しない。
- 通常規模のリポジトリで、更新開始後に処理中表示を速やかに出す。
- 長時間処理ではキャンセルまたは中断方法を検討する。
- 大量ファイルの一覧表示では、UIが操作不能にならないようにする。

### NFR-03 安全性

- Gitコマンドは固定されたサブコマンドと安全に分離した引数で実行する。
- リポジトリパス、ブランチ名、コミットメッセージをシェルのコマンド文字列として実行しない。
- 誤操作を防ぐ確認、未コミット変更の警告、処理中の多重実行防止を行う。
- 認証情報、アクセストークン、秘密鍵の内容を取得・保存・表示しない。

### NFR-04 信頼性

- Gitの終了コード、標準出力、標準エラー出力を判定して成功・失敗を明確にする。
- Gitが異常終了してもアプリ自体は可能な限り継続し、再試行または再読み込みを案内する。
- 外部変更や競合によって表示が古くなった場合は、更新を促す。

### NFR-05 保守性

- Git実行、出力解析、ドメインモデル、JavaFX画面を分離する。
- Gitコマンドの出力形式に依存する処理は一箇所に集約する。
- Gitのロケールに左右されにくい形式（例: porcelain形式）を優先する。
- 主要な状態遷移とエラー処理をヘッドレステストで検証できる構成にする。

### NFR-06 データ保存

- 初版ではGitが管理するデータを別データベースへ複製しない。
- アプリ固有の設定のみをユーザーごとの設定領域に保存する。
- 設定保存先、バックアップ方針、アンインストール時の扱いを決定する。

## 8. データと状態モデル

### 8.1 主な情報

- `Repository`: ルートパス、表示名、現在ブランチ、HEAD、リモート
- `FileChange`: パス、変更種別、ステージ状態、追加行数、削除行数
- `Branch`: 名前、現在選択中か、追跡先
- `GitOperation`: 操作名、引数の安全な表示形式、開始時刻、終了時刻、成否、出力
- `ApplicationSettings`: Gitパス、最近のリポジトリ、画面設定、テーマ

### 8.2 状態遷移

- `未選択` → `リポジトリ選択中` → `読み込み中` → `利用可能`
- `利用可能` → `操作中` → `利用可能`
- `利用可能` → `エラー表示` → `再試行またはリポジトリ再読み込み`
- `利用可能` → `外部変更検出` → `再読み込み確認`

## 9. エラー処理方針

| 分類 | 例 | 画面での対応 |
|---|---|---|
| 環境 | Gitが見つからない | 設定画面とインストール案内を表示 |
| 入力 | 空のコミットメッセージ、重複ブランチ名 | 実行前に入力欄の近くで通知 |
| リポジトリ | Git管理外、破損、ロック | 操作を中止し、対象と復旧案を表示 |
| 競合 | pullまたはcheckoutで競合 | 競合状態を明示し、ターミナルでの解決を案内 |
| 認証 | push時の認証失敗 | 認証情報を保存せず、Gitのエラーを表示 |
| 通信 | DNS、タイムアウト、接続拒否 | 再試行と接続確認を案内 |
| 入出力 | ファイル読み込み不可 | 権限やファイル状態を表示 |

エラーを握りつぶしたり、失敗を成功として画面表示したりしない。

## 10. セキュリティとプライバシー

- コマンドインジェクションを防ぐため、外部プロセスの起動方法を限定する。
- リモートURLに含まれる認証情報を画面やログに表示しない。
- Gitの環境変数、credential helper、SSH agentの秘密情報を読み取らない。
- ログにリポジトリの内容や差分を無制限に保存しない。
- 設定ファイルのアクセス権と、複数ユーザー環境での保存場所を確認する。

## 11. テスト要件

### 11.1 単体テスト

- Gitコマンドの引数生成と終了コード判定
- porcelain形式などの状態出力の解析
- ファイル状態、ブランチ状態、エラー状態の変換
- ブランチ名、コミットメッセージの入力検証
- 設定の保存・読み込み・破損時の処理

### 11.2 結合テスト

- 一時ディレクトリにGitリポジトリを作成した状態でのstatus、add、commit
- ブランチ作成、切り替え、削除
- 未追跡ファイル、削除、リネーム、コンフリクトの検出
- Git未インストールまたは不正な実行ファイル指定時の挙動

### 11.3 UIテスト

- リポジトリ選択から状態表示までの導線
- ファイル選択と差分表示
- コミット成功・失敗の表示
- 未コミット変更がある場合の確認ダイアログ
- キーボード操作、リサイズ、長いパスの表示

### 11.4 受け入れ基準

- テスト用リポジトリで、変更確認、ステージ、コミットを一連で完了できる。
- 作成したコミットが実際のGit履歴に反映される。
- 失敗したGit操作で、誤って成功表示されない。
- 未コミット変更を持つリポジトリで、危険な切り替え操作に確認が表示される。
- Git未導入環境でも、原因と対処方法を確認できる。

## 12. 開発・リリース方針

### 12.1 実装の段階

1. Git実行基盤、リポジトリ選択、status表示
2. 変更ファイル一覧、差分表示、更新
3. ステージ、アンステージ、コミット
4. ブランチ操作
5. リモート同期（fetch、pull、push）
6. 設定、操作履歴、配布パッケージ

### 12.2 リリース形態

- 開発中はMavenから起動できること。
- Windows向けにはjpackageによるアプリケーションイメージを作成し、フォルダー配布する。
- Gitの必須条件、対応OS、既知の制限をREADMEに記載する。

## 14. 初版の完了条件

次の状態になった時点で、初版の要件を満たしたと判断する。

- Gitリポジトリを選択して開ける。
- 現在のブランチと変更ファイルを確認できる。
- ファイルを選択して差分を確認できる。
- 変更をステージ・アンステージできる。
- ステージ済み変更をコミットできる。
- ブランチを作成・切り替えできる。
- 各操作の成功・失敗と、次の対処方法を確認できる。
- 未コミット変更や認証情報を不用意に失う操作を防止できる。

## 15. 決定事項

| 項目 | 決定内容 |
|---|---|
| 初版の同期範囲 | ローカルリポジトリの操作に限定し、fetch・pull・pushは将来拡張とする |
| 初版のブランチ操作 | ブランチの一覧表示・作成・切り替え・削除を含める |
| 初版のステージ粒度 | ファイル単位に限定し、ハンク・行単位は将来拡張とする |
| Gitの提供方法 | ユーザーがインストールしたGitを利用し、アプリには同梱しない |
| Gitの最小バージョン | Git 2.30以上をサポート対象とする |
| ブランチ削除の安全方針 | 現在のブランチと未マージブランチは削除不可とする |
| 初版の表示言語 | 日本語のみとする |
| 初版の配布形態 | jpackageによるWindows向けアプリケーションイメージをフォルダー配布する |
| コミットメッセージ | 空または空白のみを禁止し、形式は自由とする |
| アプリ固有のデータ保存 | Gitの状態を都度取得し、SQLiteなどのデータベースは使用しない |
| 操作履歴 | アプリ起動中だけ保持し、終了時に破棄する |
| 初版の画面構成 | リポジトリ操作を1画面に集約する |
| 状態更新 | 手動更新とアプリ内操作後の自動更新のみとし、定期ポーリングは行わない |
| コンフリクト対応 | 競合状態を表示し、解決は外部エディターやターミナルに委譲する |
| 起動時のリポジトリ | 前回開いたリポジトリを自動で開き、開けない場合は選択画面へ進む |
| 差分表示の上限 | 1ファイル10 MB以下とし、超過時は差分を表示しない |
| キーボードショートカット | 更新・ステージ・コミット・検索・終了などの基本操作に限定する |
| アクセシビリティ | キーボード操作、フォーカス表示、色以外の状態表示まで対応する |
