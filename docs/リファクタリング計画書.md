# Git GUI Windows App リファクタリング残作業計画書

## 1. 目的

本書は、2026-09-09時点で未完了のリファクタリング作業だけを記録する。完了済みの基盤整備や状態管理の作業は対象外とし、残作業の実施順序、完了条件、検証方法を定める。

リファクタリング中も、ユーザーが認識できる動作、Gitコマンドの安全な引数分離、既存設定ファイルとの互換性を維持する。機能追加やUIデザインの刷新は本書の対象外とする。

### 現在の依存方向

```text
ui (JavaFX) -> application / git / config / model
application  -> model
git          -> model
config       -> (標準Javaライブラリ)
model        -> (標準Javaライブラリ)
```

`GitGuiWindowsApp`はサービスを配線し、`ui`層の画面を構築する入口です。Gitのプロセス実行とParserは`git`層に閉じ込め、UIから個別のGit実装へ直接到達しない構成を維持します。

## 2. 残作業に共通する制約

- `GitGuiWindowsApp`はJavaFXのライフサイクルとアプリケーションの配線に限定する。
- UI以外のクラスからJavaFXコントロールを参照しない。
- `model`と`application`はJavaFX型に依存しない。
- Gitコマンドはシェルを介さず、引数リストで実行する。
- パス引数の前には`--`を置き、既存のエラー処理と割り込み処理を維持する。
- `%USERPROFILE%\.git-gui-windows-app\settings.properties`の既存キー、形式、保存場所を変更しない。
- 各作業の終了時に、関連テストと`mvnw.cmd clean install`または`mvn clean install`を実行する。
- 構造変更と機能変更を同じコミットに混在させない。

### Step 4: 画面を機能単位のView/Controllerへ分割する

#### 目的

画面構築と機能ごとのイベント処理を分離し、`GitGuiWindowsApp`の変更範囲を小さくする。

#### 作業内容

- リポジトリ・ブランチ操作を`RepositoryToolbar`相当のクラスへ移す。
- 変更一覧と差分表示を`ChangesPane`へ移す。
- ステージ・アンステージ・コミットを`CommitActionBar`へ移す。
- 履歴検索、履歴一覧、詳細表示を`HistoryPane`へ移す。
- 確認・エラー・共通スタイルのダイアログ生成を`DialogService`へ移す。
- 各Viewは`GitService`や個別のGit実装を直接呼ばず、アプリケーション層の操作を呼び出す。
- FXMLやDIフレームワークは導入せず、既存のJavaFXコードによる構築を維持する。

#### 完了条件

- `GitGuiWindowsApp`がStage、Scene、全体レイアウトの組み立て、ライフサイクル管理、依存関係の配線に限定される。
- 機能別クラスが互いのJavaFXコントロールを直接操作しない。
- 最小ウィンドウサイズ、テーマ、タブ構成、表示文言、ボタン有効条件を維持する。

#### 検証

- 起動、リポジトリ選択、変更表示、差分表示、ステージ、コミット、ブランチ操作、履歴表示をGUIで確認する。

## 5. 残作業のリスクと対策

| リスク | 対策 |
|---|---|
| UI分割時にイベントの接続が外れる | 機能単位に移動し、各移動直後に起動と操作を確認する |
| Facade移行でGit引数やエラー処理の意味が変わる | 既存テストを維持し、コマンド配列と失敗経路を比較する |
| Parserの契約変更で特殊なGit出力を失う | 正常、空、特殊文字、異常形式の入力をテストデータとして固定する |
| 設定カテゴリ分割で既存キーを読めなくなる | キーと保存先を変更せず、旧形式の読み込みテストを追加する |
| 残作業が機能追加に膨張する | 各Stepの対象外を守り、仕様変更は別の計画・コミットに分ける |
