# Git GUI Windows App リファクタリング残作業計画書

## 1. 目的

本書は、2026-09-09時点で未完了のリファクタリング作業だけを記録する。完了済みの層分離、UI分割、用途別サービスへの移行、設定既定値の集約、README更新などは対象外とする。

リファクタリング中も、ユーザーが認識できる動作、Gitコマンドの安全な引数分離、既存設定ファイルとの互換性を維持する。機能追加やUIデザインの刷新は本書の対象外とする。

## 2. 現在の依存方向

```text
ui (JavaFX) -> application / git / config / model
application  -> model
git          -> model
config       -> (標準Javaライブラリ)
model        -> (標準Javaライブラリ)
```

`GitGuiWindowsApp`はサービスを配線し、`ui`層の画面を構築する入口とする。Gitのプロセス実行とParserは`git`層に閉じ込め、UIから個別のGit実装へ直接到達しない構成を維持する。

## 3. 残作業に共通する制約

- `GitGuiWindowsApp`はJavaFXのライフサイクルとアプリケーションの配線に限定する。
- UI以外のクラスからJavaFXコントロールを参照しない。
- `model`と`application`はJavaFX型に依存しない。
- Gitコマンドはシェルを介さず、引数リストで実行する。
- パス引数の前には`--`を置き、既存のエラー処理と割り込み処理を維持する。
- `%USERPROFILE%\.git-gui-windows-app\settings.properties`の既存キー、形式、保存場所を変更しない。
- 各作業の終了時に、関連テストと`mvnw.cmd clean install`または`mvn clean install`を実行する。
- 構造変更と機能変更を同じコミットに混在させない。

## 4. 未完了作業

### Step 6: Parserとモデルの入力契約を強化する

#### 残っている作業

- `GitStatusParser`、`GitDiffParser`、`GitBranchParser`、`GitCommitParser`の入力と出力契約を明文化する。
- diff/commit Parserの区切り文字、空入力、文字コード、特殊文字、異常形式に対する扱いを整理する。
- 不正なGit出力を黙って成功扱いしないエラー境界を定める。
- `StageState`、変更種別、参照種別などの状態の組み合わせを整理する。
- 不変モデルのnull許容範囲と空コレクションの方針を明文化する。
- UI表示用の文字列生成がParserやモデルへ混在していないことを確認する。

#### 完了条件

- ParserがJavaFXに依存せず、入力文字列から明確なモデルを返す。
- 正常系、空入力、異常形式で結果とエラーの扱いが一貫している。
- 特殊文字、バイナリ、巨大差分、複数親コミットを含む入力の扱いがテストで固定されている。
- UI用の表示文言がParserやモデルに混在していない。

#### 検証

- 正常、空、特殊文字、バイナリ、巨大差分、複数親コミットのテストを追加・更新する。
- `mvnw.cmd clean test`

### Step 7: 設定のカテゴリと責務を分離する

#### 残っている作業

- ウィンドウ状態、Git実行ファイル、最近のリポジトリ、基準フォルダーを設定カテゴリ別に扱う。
- `SettingsRepository`を永続化の入口として整理し、設定値の検証を設定モデルまたは専用の検証処理へ分離する。
- `ThemeService`を設定の読み書きから独立したJavaFXテーマ適用境界として維持する。
- 設定カテゴリごとの責務と保存キーの対応を明文化する。
- 既存設定ファイルの読み込み、起動時復元、終了時保存の挙動がカテゴリ分離後も変わらないことを確認する。

#### 完了条件

- 設定カテゴリごとの責務と保存キーの対応が明確になっている。
- 設定の読み書きをJavaFXなしでテストできる。
- 既存の設定ファイルを読み込め、起動時復元と終了時保存の挙動が変わらない。

#### 検証

- `ApplicationSettingsTest`を更新して実行する。
- 一時ファイルでカテゴリ別の読み書き、既定値、破損値、重複した最近のリポジトリを確認する。
- `mvnw.cmd clean test`

### Step 8: テスト構成と移行後のコードを整理する

#### 残っている作業

- テストを`config`、`git`、`application`、`model`の責務に対応するパッケージへ整理する。
- 一時Gitリポジトリ生成の共通Fixtureを作成する。
- Git実行を差し替え可能なテスト用境界を整備する。
- UIから分離できる判断ロジックをヘッドレステストへ移す。
- 未使用クラス、旧Facade、重複ヘルパー、移行用コードを削除する。

#### 完了条件

- 構造変更後の全テストが成功する。
- 主要なGit操作、Parser、設定処理、状態判断に回帰テストがある。
- `GitGuiWindowsApp`がアプリケーションの配線とJavaFXライフサイクルに集中している。
- 未使用の旧クラスや移行用コードが残っていない。

#### 検証

```cmd
mvnw.cmd clean install
```

GUI環境では、リポジトリ選択、変更・差分、ステージ、コミット、ブランチ操作、履歴検索、テーマ切替、終了時保存を一通り手動確認する。

## 5. 実施順序と完了判定

Step 6とStep 7は、それぞれの入力契約と設定カテゴリの責務を確定させながら進める。Step 8はParser、設定、UI判断ロジックの変更が落ち着いた後に実施する。

以下をすべて満たした時点で本計画を完了とする。

- Step 6、7、8の完了条件を満たしている。
- `mvnw.cmd clean install`または`mvn clean install`が成功する。
- 現行機能の手動確認で、リファクタリング前後の挙動差がない。
- Gitコマンドの安全な引数分離と既存設定ファイルの互換性が維持されている。
- READMEとソースのパッケージ構成が一致している。
- 未使用の移行コード、重複処理、不要な互換Facadeが削除されている。

## 6. 残作業のリスクと対策

| リスク | 対策 |
|---|---|
| Parserの契約変更で特殊なGit出力を失う | 正常、空、特殊文字、異常形式の入力をテストデータとして固定する |
| 設定カテゴリ分割で既存キーを読めなくなる | キーと保存先を変更せず、旧形式の読み込みテストを追加する |
| テストFixture導入でテストが実装詳細に依存する | Git実行境界とFixtureの責務を分け、各テストが必要な状態だけを構築する |
| 残作業が機能追加に膨張する | 各Stepの対象外を守り、仕様変更は別の計画・コミットに分ける |
